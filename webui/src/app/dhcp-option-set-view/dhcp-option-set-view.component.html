Option fields and suboptions are displayed for the option {{ node.data.code }}. Hover the cursor over the option fields to see their types.

If the "always sent" tag is shown next to the option code, the option is configured to always be returned to the DHCP client, even when it is not requested. If the "never sent" tag is shown, the option is configured to never be returned to the DHCP client, even when it is requested. The "empty option" and "empty suboption" tags indicate that the configured DHCP option contains no payload.

The "always sent" and "never sent" settings are sticky, meaning they do not follow the usual configuration inheritance rules. Instead, if they are enabled at least once along the configuration inheritance chain, they are applied - even if they are disabled in other places which would normally receive a higher priority. For instance, if one of the flags is enabled in the global scope, but disabled at the subnet level, it is enabled, disregarding the subnet-level setting.

The "never sent" setting has precedence over "always sent", so if both are true the option is not added.

The "{{ node.data.level }}" tag is shown when DHCP options are inherited from multiple configuration levels; it indicates that the option has been defined at the level presented by the tag.
